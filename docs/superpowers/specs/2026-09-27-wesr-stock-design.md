- 日期：2026-09-27
- 状态：待评审
- 设计稿：`design/pages-mockup.html`（1:1 像素，改完可重渲染）
- 硬件资料与知识库：`KNOWLEDGE.md`、`references/`

## 1. 目标与范围

把这台 4.2 英寸全反射屏开发板做成一台“桌面摆件式看盘器”：默认看起来是个带温湿度的时钟，按键切页后才是股票信息；手机上用微信小程序配网、选股。

范围内：

- 固件：4 个页面 + 状态条、按键交互、WiFi 联网、行情抓取与解析、分时图绘制、BLE 配网
- 小程序：设备连接、WiFi 配网、股票池与刷新间隔设置（3 屏）
- 行情数据来自公开接口（方案 A：板子直连，无自建服务器）

范围外（v1 明确不做）：OTA 升级、SD 卡历史缓存、天气、港美股/多市场、自建后端服务、音频（ES8311/ES7210 硬件闲置）、触屏交互（本板无触摸）。

## 2. 硬件与约束

| 项目 | 值 | 对设计的影响 |
| --- | --- | --- |
| 屏幕 | 4.2" 全反射 RLCD，控制器 ST7305，**400×300 横屏**，**1-bit 黑白** | 只能纯黑/纯白：无灰度、无红绿、无半透明；图形靠图案与线型区分 |
| 屏幕特性 | 无背光，靠环境光反射成像 | 暗环境对比度低：少用细线、避免大片反白（反白只留给需要用户动作的提示） |
| 主控 | ESP32-S3-WROOM-1-N16R8（16MB Flash + 8MB PSRAM） | 字体与资源宽裕，PSRAM 可放 LVGL 缓冲 |
| 内存 | 512KB SRAM | 分时缓存按页懒加载（见 §5） |
| 供电 | 18650 电池 + 充放电管理，出厂程序实测待机约 24h | 刷新策略必须省电：只拉当前页、休市不请求 |
| 按键 | KEY = GPIO18，BOOT = GPIO0，PWR = 硬开关（不走固件） | 只用 KEY，三个动作：单击/双击/长按 |
| 传感器 | SHTC3 温湿度（I2C 0x70） | 第 1 页温湿度是本地数据，断网/未配网照样显示 |
| RTC | PCF85063（I2C 0x51）+ 可充电 ML1220 备用电池 | 断电走时；时间来源见 §12 |
| 引脚 | 见 `KNOWLEDGE.md` §2 | 直接复用官方 BSP，不重定义 |

## 3. 系统架构

```
[腾讯公开接口]                 [手机微信小程序]
      │ HTTPS                      │ BLE (NUS)
      ▼                            ▼
┌───────────────────────────────────────────────┐
│ 固件 (ESP-IDF 5.5.x, C++)                      │
│  net_task    行情拉取 / SNTP / 连接管理         │
│  ui_task     LVGL 渲染 + 页面状态机 (20ms tick) │
│  input_task  KEY 单击/双击/长按                 │
│  ble_task    配网模式下的 BLE 服务与命令处理     │
│  sensor_task SHTC3 + 电池 ADC                  │
│         共享 AppState（互斥锁 + 版本号）         │
└───────────────────────────────────────────────┘
      │ SPI                     │ I2C
      ▼                         ▼
   ST7305 屏               SHTC3 / PCF85063 / 电量 ADC
```

- 无自建服务器：板子直连腾讯公开接口；小程序只做配置下发与状态回读，不参与行情抓取。
- 固件基于官方 `10_FactoryProgram` 裁剪，复用 `port_bsp`（I2C / SPI 屏 / SD / ADC / 按键）、`app_bsp`（WiFi / LVGL 移植）、`ExternLib`（multi_button）。
- **不重写屏驱动**：ST7305 的初始化序列和查表优化都在官方 `display_bsp` 里，直接用。
- LVGL 用 **v8**，与 `10_FactoryProgram` 一致，避免 v8/v9 API 混用。

## 4. 数据源（字段已实测核对）

### 4.1 实时快照（第 1 页用，一次拿 8 只）

```
GET https://qt.gtimg.cn/q=sh600519,sz000858,sz002594,sh600036,sh601318,sh000300,sz000858,sh600900
```

- 响应 `Content-Type: text/html; charset=GBK`，每行一条：`v_<code>="a~b~c~...";`
- 实测单次 8 个代码可用（HTTP 200，返回 8 行）；固件限制单次不超过 8 个
- 字段下标（`~` 分隔，从 0 起）：

| 下标 | 含义 | 实测示例 |
| --- | --- | --- |
| 1 | 名称（**GBK 中文**） | 贵州茅台 |
| 2 | 代码 | 600519 |
| 3 | 现价 | 1237.00 |
| 4 | 昨收 | 1251.24 |
| 5 | 今开 | 1250.01 |
| 30 | 时间戳 `yyyymmddHHMMSS` | 20260924161444 |
| 31 | 涨跌额 | -14.24 |
| 32 | 涨跌幅 % | -1.14 |
| 33 | 最高 | 1256.13 |
| 34 | 最低 | 1231.05 |
| 36 | 成交量（手） | 31239 |
| 37 | 成交额（万元） | 386731 |

**中文名不解析**：股票全名与首字都来自小程序下发的本地配置（UTF-8），固件只取数字字段，因此不需要 GBK→UTF-8 转换表，也省掉编码这一层坑。

### 4.2 分时数据（第 2、3 页用，单只一次）

```
GET https://web.ifzq.gtimg.cn/appstock/app/minute/query?code=sh600519
```

- **必须走 HTTPS**：HTTP 会 302 跳到 HTTPS，直接请求 HTTPS 少一次往返。
- **不支持逗号批量**：多代码返回 `{"code":-1,"msg":"code param error"}`，所以 4 只 = 4 次请求（复用同一条 TLS 连接）。
- 结构：`data.<code>.data.data = ["HHMM 价格 累计量(手) 累计额(元)", ...]`，另有 `data.<code>.data.date = "YYYYMMDD"`。
- **同一响应里自带快照**：`data.<code>.qt.<code>` 是 JSON 字符串数组，下标与 §4.1 相同（3=现价、4=昨收、5=今开、32=涨跌幅…），中文名是 `\uXXXX` 转义 —— **这个接口完全没有 GBK 问题**。所以第 2、3 页只发 1 次请求，就能同时拿到分时、现价、昨收（画昨收基准线要用的值就在这）。
- **同一响应里自带市场状态**：`data.<code>.qt.market[0]` = `"2026-09-27 01:14:22|HK_close_已休市|SH_close_中秋节休市|SZ_close_中秋节休市|US_close_已休市|..."`，取 `|SH_` 后面紧跟的是 `close` 还是 `open` 即可。
- 实测 `sh600519`：**267 个点**（首点 `0930 1250.01 183 22875182.71`，末点 `1530 1237.00 31245 3868009791.36`）——**不要假设 240 点**，按实际点数绘制。
- 均价 = `累计额 ÷ (累计量 × 100)`（累计量单位是手）。自校验：首点算得 1250.01，与价格一致。

### 4.3 休市判定（两级，不维护节假日表）

1. **本地兜底**：设备本地时间不在交易时段（§14）→ 压根不发请求，省电；
2. **服务端权威**：分时响应里 `qt.market[0]` 的 `SH_`/`SZ_` 状态若为 `close` → 判定休市，顶栏显示细线状态条「休市 · 显示 MM-DD 收盘数据」，`MM-DD` 取响应里的 `data.<code>.data.date`。

比"拿日期对比"更准：节假日（例如实测抓到的中秋节休市）也会被判出来，而且不依赖设备时钟和服务器日期能不能对上。

### 4.4 请求与容错

- TLS 用 ESP-IDF 的 `esp_crt_bundle`（内置根证书）校验；握手失败时允许降级为不校验并只打串口警告。这是**有意的取舍**：公开行情数据、无凭证、无隐私，用可用性换掉一点完整性保证。
- 解析按位置取值，字段数不足即丢弃整条；价格 ≤ 0、非数字、NaN 一律按无数据处理。
- 失败时保留上一份成功数据并计数；连续失败 5 次 → 状态条「未联网」。

## 5. 刷新策略（方案 A：只刷当前页）

| 当前页 | 拉取内容 | 请求数 |
| --- | --- | --- |
| 第 1 页 | 8 只实时快照（批量） | 1 |
| 第 2 页 | 当前组的 4 只分时 | 4 |
| 第 3 页 | 当前选中 1 只分时 | 1 |
| 第 4 页 | 不发请求（只读状态） | 0 |

- **交易时段**（09:15–11:30、13:00–15:00，含集合竞价）每 15 秒刷一次；非交易时段不请求，保持收盘数据。
- 页面首次进入且缓存为空：显示 `—` 与「加载中」，拿到数据再重绘，不画假数据。
- 切页：缓存 TTL 未过期就立即用缓存渲染（**切页必须 < 100ms**），同时后台补一次刷新。
- 缓存按页独立、TTL 15 秒：页 1 = 8 只快照；页 2 = 当前组 4 只分时（切组即作废）；页 3 = 单只分时（换股即作废）。
- 失败退避：5s → 10s → 20s → 30s（封顶），成功后恢复 15s。

## 6. 数据模型与持久化

```cpp
struct StockCfg {            // 来自小程序，存 NVS
    char code[12];           // "sh600519"，格式校验
    char name[32];           // UTF-8 全名，第 2/3 页显示
    char mark[8];            // 第 1 页首字，默认取 name 第一个字，可手改 1–2 字
};

struct Quote {               // 快照
    float last, prev_close, open, high, low, chg, chg_pct;
    uint32_t vol_hands;
    uint32_t stamp;          // 接口字段 30
    bool valid;              // false = 停牌 / 无数据 / 未拉到
};

struct Minute {              // 分时点
    uint16_t hhmm;           // 0930
    float price, avg;
};

struct MinuteSet {
    Minute pts[300];         // 实测 267 点，留余量；不假设 240
    uint16_t n;
    uint32_t day;            // 接口 date
    bool valid;
};

struct AppCfg {              // NVS
    char ssid[33], pass[65];
    StockCfg stocks[8];
    uint8_t count;           // 0–8
    uint16_t refresh_sec;    // 默认 15
};
```

- NVS 保存 `AppCfg`；掉电重启后配置、WiFi、股票池都在。
- 内存里只放当前页需要的缓存（§5），不常驻 8 只分时。

## 7. 界面规格（400×300，1-bit）

顶栏四页共用（24px 高）：WiFi 图标 12×10 → 蓝牙图标 9×12 → 弹簧 → 页码点 4×5px → 组方块 2×（7×3）→ 弹簧 → 电量文本 11px + 电池图标 19×10。

状态条贴在顶栏下方：普通状态 = 细线分隔的白底黑字（9px，居中）；需要用户动手的状态（未联网 / 未配网 / 配网模式）= **反白**（黑底白字），这是 1-bit 下最醒目的做法。

| 页面 | 布局 | 关键尺寸 |
| --- | --- | --- |
| 1 时钟看盘 | 左 300px / 右 100px | 时钟 78px；日期 16px；底部温度/湿度两栏（标签 16px + 数值 19px）；右栏 8 行各 34px，行内「首字 16px + 涨跌 12px」与「现价 14/12px」，行间 1px 分隔线 |
| 2 四宫格 | 2×2，各 200×138（十字线即格线） | 名称 16px + 涨跌 12px + 现价 16px + 分时图 184×86 |
| 3 个股分时 | 标题 + 现价 + 大图 + 开高低收量 | 名称 16px + 位置 `n/8` 9px；现价 25px；涨跌 14px；图例 16px；分时图 380×156（含量柱）；OHLC 行 12px |

涨跌幅统一是「`▲`/`▼` + **一个空格** + 数字 + `%`」：1bpp 点阵里箭头字形比它自己的步进宽，紧贴数字会咬到一起（板上实测），所以格式化时固定留一个空格；字号也按上表放大过一档（用户反馈 9–11px 偏小）。
| 4 系统状态 | 双栏 | 栏题 10px + 行 10px（网络 / 电源环境 / 行情 / 系统） |

分时图的 1-bit 画法（没有红绿，靠线型和图案区分）：

- 价格线：实线 1.2–1.5px
- 均价线：虚线 2.5/2
- 昨收基准：横虚线 3/2，纵轴以昨收为中心上下对称
- 涨/跌面积：45° 斜纹填充（4px 周期、0.8px 线宽），只在大图用；四宫格小图不填，避免糊成一片
- 成交量：图区下方 20px 独立条；时间轴刻度文字 8px；大图左角标当日最大/最小涨跌幅
- 横轴映射：09:30→0、11:30→120、13:00→121、15:00→241 分钟序号，午休 11:30–13:00 在横轴上压掉，超出 09:30–15:00 的点（实测有 15:30）clamp 到右边界

## 8. 交互

| 动作 | 判定 | 行为 |
| --- | --- | --- |
| 单击 | 按下抬起，400ms 内无第二次按下 | 切页 1→2→3→4→1 |
| 双击 | 两次单击间隔 < 400ms | 第 2 页切第 1/2 组；第 3 页 `idx = (idx+1) % count`；页面不跳 |
| 长按 | 按住 ≥ 3000ms | 进入配网模式（BLE 广播 + 反白状态条） |

长按不触发单击/双击。**第 1、4 页双击无动作**（那两页没有可切的股票，免得误触造成看不见的状态变化）。**配网模式中单击/双击不生效**，长按 3 秒退出配网并回到进入前的页面。用官方 `ExternLib/multi_button` 事件回调实现，不自写去抖。

## 9. 边界规则（固件按这 14 条实现）

1. 股票池上限 8 只，按下标 0–7 固定占位；不足就留空，不补位、不重复、不抽稀
2. 0 只：第 1 页右栏整列留空；第 2 页四格全空；第 3 页显示「未配置股票」；第 4 页股票池 0；双击无动作
3. 1–4 只：第 2 页只有组 1，双击无效，顶栏只显示 1 个组方块
4. 5–8 只：组 2 固定放第 5–8 只，缺的格位留空
5. 第 3 页索引 `(idx+1) % count` 回绕；配置被改小后 `idx = min(idx, count-1)`，防越界
6. 停牌 / 无数据：现价、涨跌、均价统一显示 `—`，分时区不画线（画假直线比留白更误导）
7. 涨跌幅为 0：显示 `0.00%`，不加 ▲▼
8. 昨收为 0 或缺失：整块显示 `—` 且不画图（防除零）；负价、NaN 一律当无数据丢弃
9. 分时点数不足（开盘不久）：只画已有那段，右侧留白；刻度线仍按整天比例画，不压缩
10. 数值排版：A 股与指数都 2 位小数；价格整数部分 ≥4 位时字号从 14px 降到 12px 兜底（`1682.50`、`12345.67` 都走这条），避免顶破 100px 栏宽
11. 单只涨幅 >10%（新股 / 退市整理）：分时纵轴按实际数据算，不写死 ±10%
12. 刷新失败：沿用上一次数据，第 4 页「今日失败」+1；连续 5 次失败 → 状态条「未联网」
13. 首字冲突（中国平安 / 中国太保都取「中」）：默认退回显示前两个字，小程序可手改 1–2 字
14. 按键定稿：单击=切页、双击=换股（不跳页）、长按 3 秒=进配网；无手动刷新，行情全自动

## 10. BLE 配网协议

用 Nordic UART Service（NUS）：固件侧和手机侧都有成熟实现，不用自己造 GATT。

| 角色 | UUID |
| --- | --- |
| Service | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` |
| RX（小程序写，板子收） | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` |
| TX（板子发，小程序订阅 notify） | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` |

- 报文：UTF-8 JSON + `\n` 结尾。**单包固定 ≤ 20 字节**（iOS 不支持 `wx.setBLEMTU`，用 20 最稳）；长报文分片发送，接收端按 `\n` 重组，单条报文上限 4KB，超限丢弃本次会话。
- 进入配网：长按 KEY 3 秒 → BLE 广播 + 反白状态条「配网模式 · 等待小程序」；3 分钟无操作自动退出（停止广播，回正常显示）。
- 已连上 WiFi 时进入配网不主动断网；未连接时不主动扫描，收到 `scan` 才扫（省电）。

命令（小程序 → 板子）：

| cmd | 参数 | 说明 |
| --- | --- | --- |
| `hello` | — | 握手，板子回 `status` |
| `scan` | — | 触发 WiFi 扫描，回 `scanResult`（最多 12 个 2.4G，按信号排序） |
| `setWifi` | ssid, pass | 存 NVS 并连接，回 `ack` / `err` |
| `getCfg` | — | 回 `cfg`（股票池 + 刷新间隔 + 首字） |
| `setStocks` | items[≤8] {code, name, mark?} | 校验后存 NVS，回 `ack` / `err` |
| `setInterval` | sec (5/10/15/30/60) | 回 `ack` |
| `timeSync` | unix | 写 RTC，回 `ack` |
| `exit` | — | 退出配网模式 |

事件（板子 → 小程序）：`status` / `scanResult` / `cfg` / `ack` / `err`。
`status` 字段：fw、mac、battery_pct、battery_mv、wifi{ssid, ip, rssi, state}、cfg_count、page、group、idx。

错误码：`E_CODE_FMT`（代码不是 `sh|sz|bj` + 6 位）、`E_TOO_MANY`（>8）、`E_SSID`（空或 >32）、`E_PASS`（>64）、`E_NVS`、`E_WIFI`（连接失败/密码错）。

WiFi 密码只在小程序→板子的方向传输并落 NVS；**不支持回读**，小程序里也不存密码明文。

## 11. 微信小程序

三屏：

1. 设备：扫描 → 连接 → 显示设备状态（固件、电量、WiFi、IP、RSSI）；页面顶部提示「板子需先长按 KEY 3 秒进入配网模式」。
2. 配网：显示板子扫到的 2.4G 网络列表 → 选 SSID + 输密码 → 保存并连接 → 显示结果与板端 IP。
3. 股票设置：8 只列表（增删、排序、显示全名与首字）、刷新间隔、同步到设备、从设备读回。

技术要点：

- 只用 BLE 相关 API（`openBluetoothAdapter` / `startBluetoothDevicesDiscovery` 带 service UUID 过滤 / `createBLEConnection` / `notifyBLECharacteristicValueChange` / `writeBLECharacteristicValue`）；**不用 `wx.request`** —— 局域网 IP 在生产环境过不了域名白名单。
- 分包固定 20 字节，不依赖 MTU 协商。
- 本地缓存用 `wx.setStorageSync` 存最近一次设备与股票列表，重进页面直接回填。
- 错误提示：蓝牙未开 → 引导开启；连接失败 → 提示靠近重试；密码错 → 红字提示并留在配网屏；股票超过 8 只 → 直接拦住。
- 首字默认自动取股票名第一个字，撞车时才提示手改；不做行情 K 线展示（那是板子的活）。

## 12. 时间与 RTC

- 正常路径：配网成功后 SNTP 校时（`ntp.aliyun.com` 主、`pool.ntp.org` 备）→ 写入 PCF85063；之后每 6 小时校一次。
- 兜底：配网时小程序发 `timeSync`（手机时间，秒级精度），首次开机没网也能有大致正确的时间。
- 显示刷新：ui_task 每 60 秒读一次 RTC 更新时间区，不每秒刷屏（省电，1-bit 屏每秒刷毫无意义）。
- 断电：ML1220 保持走时；电池完全断开则时间复位，下次配网自动校准。
- 时区固定 Asia/Shanghai（UTC+8），v1 不做时区设置。

## 13. 错误处理与可观测

- 第 4 页就是排障面板：WiFi/信号/IP/蓝牙、电池电压与百分比、充电状态、温湿度、SD 卡、数据源、刷新间隔、更新时间、今日失败次数、股票池规模、第 2 页组、第 3 页位置、固件版本、运行时长、Heap/PSRAM。
- 串口日志（115200）：`[net] req=... code=... ms=...`、`[net] parse err field=...`、`[ble] cmd=... len=...`。
- 看门狗：ui/net 任务接 `esp_task_wdt`，30 秒未喂狗即重启。
- 低电提示：电压 < 3.3V 时第 1 页电量文字用反白闪烁（复用现有元素，不加新控件）；不做自动关机。
- 不做遥测上传（没有服务器，也不该把用户持仓传出去）。

## 15. 测试与验收

host 侧单测（gcc 跑的 assert 程序，不依赖硬件，放在 `test/`，配套真实响应 fixture）：

1. 快照解析：GBK 字节流里只取数值字段；字段缺失/截断不崩
2. 分时解析：点数不固定（实测 267）、字段缺失、`date` 不是今天 → 休市
3. 均价计算：`累计额/(累计量×100)`；累计量为 0 → 无数据
4. 涨跌格式化：0 → `0.00%`、正负号、≥5 位整数降字号判定
5. 边界规则 1–14 全覆盖（0 只 / 1–4 只 / 5–8 只、停牌、索引回绕、切组边界）
6. 横轴映射：0930→0、1130→120、1300→121、1500→241、1530→241
7. 按键状态机：喂时间戳，验证单击/双击/长按互斥

fixture：把本次抓到的真实响应（快照 GBK 文本、分时 JSON）存进 `test/fixtures/`，测试只跑 fixture，不依赖网络。

上板冒烟清单（8 项，手工）：

1. 未配网首屏：状态条反白、时钟在走、温湿度有值、右栏留空
2. 配网：长按 3 秒 → 小程序连上 → 下发 WiFi → 连上后时间自动校正
3. 第 1 页：8 只快照、行分隔线、首字正确
4. 第 2 页：四格分时 + 双击切组（组方块跟着变）
5. 第 3 页：分时大图（斜纹/均价/成交量/时间轴）+ 双击换股 + `n/8`
6. 第 4 页：字段齐全，失败计数会动
7. 断网/拔电重连：状态条「未联网」→ 恢复后自动回正常
8. 边界：只配 2 只、配 1 只停牌股，屏幕不崩也不画假线

验收标准：上板 8 项全过；host 单测全绿；切页 < 100ms；连续 24h 运行无重启且 Heap 曲线平稳。

## 17. 风险与取舍

| 风险 | 处理 |
| --- | --- |
| 公开接口非官方，可能改格式或限流 | 解析按位置取值 + 失败退避 + fixture 回归；接口真坏了只改一个解析模块 |
| TLS 根证书不匹配 | 降级为不校验 + 串口告警（公开数据、无凭证） |
| 续航不达预期 | 只拉当前页 + 休市不请求 + 15s 间隔；还不够就把默认改 30s（一个常量） |
| 1-bit 屏刷新残影 | 全屏刷新（15KB / 次）；若闪烁改为仅在数据变化时刷；官方 U8G2 例程实测 74FPS，有富余 |
| 中文字体体积 | 3500 常用字两档约 175KB Flash（共 16MB）；缺字显示 `?` 而不是崩 |
| 腾讯接口对非浏览器请求限流 | 带正常 UA 与 Referer；失败退避；必要时退回新浪快照（只做第 1 页） |
